# Salesbot — Телеграм-бот приёма заказов на хлеб

## Назначение

Бот принимает заказы на хлеб от пользователей Telegram, управляет календарём дат выдачи, ведёт ассортимент и уведомляет через две раздельные группы: одну для заказов, другую для команд администраторов.

## Внешние файлы конфигурации

| Файл | Формат | Назначение |
|------|--------|------------|
| `config/token.txt` | Plaintext | Токен бота |
| `config/admins.txt` | По одному на строку: username или числовой ID | Администраторы бота |
| `config/group_notify.txt` | Plaintext, числовой ID | Группа уведомлений о заказах |
| `config/group_admin.txt` | Plaintext, числовой ID | Группа для команд администраторов |
| `data/bread.csv` | CSV без заголовка: `название,цена` | Ассортимент хлеба |
| `data/calendar.json` | JSON-массив строк `"YYYYMMDD"` | Активные даты выдачи |
| `data/orders.json` | JSON-массив объектов заказа | Все активные заказы |
| `data/fsm_storage.pkl` | Pickle | Сессии FSM (корзины пользователей) |

`admins.txt` поддерживает оба формата: числовой ID (`123456789`) и username без @ (`Dreammuch`). Сравнение username производится без учёта регистра.

## Логика календаря

### Автогенерация дат
- По умолчанию дни выдачи: **среда** и **суббота**.
- При старте и ежедневно в 00:01 генерируются даты на 4 недели вперёд и сохраняются в `calendar.json`.
- Ручные даты, добавленные через `/dateadd`, хранятся в том же файле.
- Удалённые через `/dateremove` — исключаются.

### Дедлайн приёма заказов
- Заказ принимается до **20:00 за двое суток до даты выдачи** (T−2).
  - Среда → дедлайн пн 20:00
  - Суббота → дедлайн чт 20:00
- При показе дат отображаются только те, дедлайн которых ещё не наступил.
- Пользователю показываются **3 ближайшие** доступные даты.
- Дедлайн отображается **внутри кнопки** выбора даты: `18 марта (ср)  ·  заказ до 20:00 16.03 (пн)` — в тексте сообщения дедлайн не дублируется.
- Дни недели — сокращённо: пн, вт, ср, чт, пт, сб, вс.

## Пользовательский сценарий (FSM)

```
[/start / любое сообщение вне сценария / таймаут 10 мин]
  │
  ▼
Главное меню (ReplyKeyboard, только private-чат)
  • [📋 Ассортимент и цены]   ← верхняя кнопка
  • [🛒 Новый заказ]          ← нижняя кнопка

  ├── [📋 Ассортимент и цены]
  │     Выводит список хлеба с ценами, остаётся в главном меню
  │
  └── [🛒 Новый заказ]
        │
        ▼
      Шаг 1 — Выбор даты
        • Inline-кнопки: 3 ближайшие доступные даты
        • Текст кнопки: "18 марта (ср)  ·  заказ до 20:00 16.03 (пн)"
        │
        ▼
      Шаг 2 — Выбор хлеба
        • Inline-сетка: ассортимент в 2 колонки (только название, без цены)
        • При выборе — счётчик "×N" на кнопке
        • Корзина с ценами отображается в тексте сообщения
        • Кнопка [🛒 ЗАКАЗАТЬ] внизу (полная ширина, капслок)
        • Каждое нажатие добавляет +1 единицу
        │
        ▼
      Шаг 3 — Корзина / подтверждение
        • Список: название × кол-во — сумма ₽
        • Итоговая сумма
        • Кнопки [❌ Название ×N — сумма] — удалить позицию
        • [✅ РАЗМЕСТИТЬ ЗАКАЗ] (капслок)  [◀️ Назад]
        │
        ├── [◀️ Назад] → Шаг 2 (корзина сохраняется)
        │
        └── [✅ РАЗМЕСТИТЬ ЗАКАЗ]
              • Пользователю: "✅ Заказ принят! С вами свяжутся для уточнения деталей."
              • В group_notify: состав заказа, дата, Telegram ID
              • Заказ сохраняется в orders.json
              • Показывается главное меню
```

### Таймаут неактивности
- Если пользователь в активном сценарии не нажимал кнопки **более 10 минут**, при следующем сообщении сценарий сбрасывается и показывается главное меню ("Сессия истекла").
- Время последней активности хранится в in-memory dict `_last_activity` (сбрасывается при рестарте).

### Персистентность FSM
- Сессии корзин (состояние FSM + данные) сохраняются в `data/fsm_storage.pkl`.
- При рестарте бота пользователь продолжает с того места, где остановился.

## Хранение заказа (структура объекта)

```json
{
  "order_id": "uuid",
  "user_id": 123456789,
  "username": "username_или_null",
  "date": "20260318",
  "items": [
    {"name": "Бородинский", "price": 150, "qty": 2},
    {"name": "Ржаной", "price": 120, "qty": 1}
  ],
  "total": 420,
  "created_at": "2026-03-14T18:30:00"
}
```

Заказы автоматически удаляются из `orders.json` после наступления даты выдачи (ежедневно в 00:05).

## Уведомления в группы

### group_notify — при размещении заказа
```
📦 Новый заказ
Дата выдачи: 18 марта (ср)
Пользователь: @username (ID: 123456789)

Бородинский × 2 — 300 ₽
Ржаной × 1 — 120 ₽
──────────────
Итого: 420 ₽
```

### group_notify — ежедневный итог (21:00)
- Бот проверяет все заказы, созданные за текущий день.
- Если заказов нет — сообщение не отправляется.
- Если есть — сводка по каждой дате выдачи: суммарное количество каждого хлеба.

### group_admin
- Только ответы на команды администраторов.
- Все ответы включают `ReplyKeyboardRemove` — кнопки в группе не показываются.
- Сообщения от не-администраторов и из других групп молча игнорируются.

## Команды администраторов

Принимаются **только из `group_admin`** и **только от пользователей из `admins.txt`**.

| Команда | Описание |
|---------|----------|
| `/dateadd YYYYMMDD` | Добавить дату в календарь |
| `/dateremove YYYYMMDD` | Удалить дату из календаря |
| `/datedisplay` | Показать 6 ближайших активных дат |
| `/breadadd Название, цена` | Добавить хлеб в ассортимент |
| `/breadremove Название` | Удалить хлеб из ассортимента |
| `/breadlist` | Показать текущий ассортимент |
| `/orders` | Заказы на 3 ближайшие даты (даты без заказов не показываются) |
| `/bake` | Сколько чего печь на 3 ближайшие даты (только будущие, без сегодня); позиции вне ассортимента показываются внутри блока каждой даты с ⚠️ |
| `/help` | Справка по командам |

## Планировщик (APScheduler, timezone: Europe/Moscow)

| Время | Задача |
|-------|--------|
| 00:01 | Дополнить `calendar.json` датами на 4 недели вперёд |
| 00:05 | Удалить из `orders.json` заказы с истёкшей датой выдачи |
| 21:00 | Отправить суточный итог заказов в `group_notify` |

## Ограничения и правила

1. Токен и конфиги хранятся только в файлах `config/` — никогда в коде.
2. User-роутер фильтруется на уровне aiogram: только `chat.type == "private"`.
3. Admin-роутер фильтруется на уровне aiogram: только `chat.id == group_admin_id`.
4. Команды администраторов в личных сообщениях игнорируются.
5. Бот не принимает заказы после дедлайна — дата исчезает из списка автоматически.
6. При удалении хлеба из ассортимента уже сохранённые заказы не изменяются.
7. Две группы независимы: можно указать одинаковый ID в обоих файлах.
8. Кнопки (ReplyKeyboard) отображаются только в личных чатах пользователей.
